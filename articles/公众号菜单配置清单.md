# 「Web开发技能」菜单后台配置清单 v2

> ⚠️ **v2 修订原因（2026-09-28）**：本号**未完成微信认证**，菜单「跳转网页」填 GitHub 时后台报
> **「发布失败，链接内容不属于当前公众号」**。这不是配置错误，是账号类型的硬限制。
> v1 里「发送消息 → 回复类型选文字」也是错的：未认证号的菜单动作**不支持纯文字**。

## 〇、先记住这条平台规则

| 账号类型 | 【跳转网页】能填什么 | 【发送消息】能选什么 |
| --- | --- | --- |
| **未认证（本号现在）** | **只能填本号自己的内容**：页面模板、合集、公众号主页、历史消息页、已发表的文章 | 只能选**图文消息**（不支持纯文字） |
| 已完成微信认证 | 可填任意外链（GitHub、你的工具页都行） | 文字 + 图文都可 |

由此推出三个必须接受的事实：

1. **GitHub、工具页、幼儿学堂链接，现在一律进不了菜单**，别再试了，会一直报「链接内容不属于当前公众号」。
2. **外链唯一可靠的入口是「关键词自动回复」**：自动回复的文字消息里带 URL，用户在对话窗口里点就能打开（这个不受菜单限制）。
3. 菜单项要变成**「引导用户去发关键词」**的入口，而不是直接的链接。

## 一、修正后的菜单动作对照表

| 所属一级 | 二级菜单名 | 菜单动作 | 具体怎么填 |
| --- | --- | --- | --- |
| 学技能 | 前端实战 | 发送消息 | 图文消息 → 选已有的前端文章（或指向「合集」） |
| 学技能 | 全栈部署 | 发送消息 | 图文消息 → 对应文章 |
| 学技能 | AI 提效 | 发送消息 | 图文消息 → 对应文章 |
| 学技能 | 全部文章 | **跳转网页** | 填**合集 / 页面模板链接**（这是官方明确允许的，唯一能用跳转网页的项） |
| 看作品 | 幼儿学堂 | 发送消息 | 图文消息 → 选《我做过的东西，怎么拿到》那篇 |
| 看作品 | 在线工具 | 发送消息 | 同上（同一篇） |
| 看作品 | 开源代码 | 发送消息 | 同上（同一篇） |
| 看作品 | 作品清单 | 发送消息 | 图文消息 → 同上 |
| 找我 | 关于作者 | 发送消息 | 图文消息 → 《关于我》那篇，或选一篇带作者介绍的旧文 |
| 找我 | 加群交流 | 发送消息 | 图文消息 → 内含群二维码的那篇 |
| 找我 | 合作投稿 | 发送消息 | 图文消息 → 含联系方式的那篇 |
| 找我 | 提问留言 | 发送消息 | 图文消息 → 含提问引导的那篇 |

要点：

- **「看作品」四项共用同一篇图文**是刻意的：菜单只是入口，用户点进来看到内容再决定去哪，比在菜单里堆四个死链好。
- 菜单名**不要**写成「源码」这种动词，用户会以为是直接给代码；写「开源代码」他会点进图文，图文明说「回复『源码』拿链接」。
- 如果某一项暂时没内容可挂，**宁可先不建这一项**，也不要挂一个点开是空的图文。

## 二、关键词自动回复（外链的真正出口）

路径：**自动回复 → 关键词回复 → 添加回复**

| 关键词 | 匹配方式 | 回复类型 | 回复内容 |
| --- | --- | --- | --- |
| 源码 | 半匹配 | 文字 | 「源码在这儿：https://github.com/⟨你的用户名⟩ 有问题直接在仓库提 issue，我都会回。」 |
| 工具 | 半匹配 | 文字 | 「我常做的小工具都放这：⟨工具页链接⟩」 |
| 幼儿学堂 | 半匹配 | 文字 | 「这是我给孩子写的网页，打开就能玩：⟨站点链接⟩ 想要这份文件直接说，拷过去就能用。」 |
| 前端 | 半匹配 | 文字 / 图文 | 「前端实战合集都在这儿了，慢慢看 👇」（攒够 4 篇后改成图文消息） |
| 全栈 | 半匹配 | 文字 / 图文 | 「从写接口到部署上线，这一组讲得比较细 👇」 |
| ai、AI | 半匹配 | 文字 / 图文 | 「AI 辅助开发的实战记录都在这 👇」 |
| 全部文章 | 全匹配 | 文字 | 「全部文章目录：⟨合集链接⟩」 |
| 作品 | 半匹配 | 文字 | 「作品和获取方式都在这篇：⟨那篇图文的链接⟩」 |
| 关于 | 半匹配 | 文字 | 全文见 `articles/关于作者.md` 版本 A |
| 加群 | 半匹配 | 图片 | 群二维码（**7 天过期，每周一换**；或用长期活码） |
| 合作 | 半匹配 | 文字 | 「投稿与合作：⟨邮箱⟩，或加微信注明来意，一般 24 小时内回。」 |
| 提问 | 半匹配 | 文字 | 「有问题直接发消息：想要什么效果 + 你的代码或报错截图 + 已经试过什么。这样我一次就能答上。」 |

⚠️ 关键词回复支持**文字**（这个不受菜单限制），所以**所有外链都放在文字回复里**——用户点击即可打开，体验和菜单外链几乎一样。

## 三、要新增一篇图文：《我做过的东西，怎么拿到》

这是 v2 的关键动作，用来接住「看作品」那四个菜单项。正文结构建议：

1. 一句话说清：我做过什么，分别在哪儿
2. 导航站：功能一句话 + 在哪打开
3. 幼儿学堂：一张界面图 + 「回复『幼儿学堂』获取」
4. 开源代码：仓库地址（写成 `github.com/xxx` 纯文本也保留一份，万一链接不给点还能复制）
5. 工具页
6. 结尾：「想直接聊，回复『关于』」

⚠️ 正文里的外链能不能点，取决于账号是否有超链接权限——发布后**自己用手机点一遍**确认。不能点就退化成纯文本地址，并引导「回复关键词拿可点链接」。

## 五、发布与自测

1. 先建关键词回复，**再**建菜单（顺序反了会出现点了没反应的死菜单）。
2. 菜单点「保存并发布」，**24 小时内**全量生效；想立刻看到就取关再关注。
3. 逐个点完菜单项，再逐个发一遍关键词（含半匹配测试，如「前端怎么学」）。
4. 「全部文章」那项发布后，在手机上手点确认合集链接能打开。
