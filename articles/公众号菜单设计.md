# 「Web开发技能」公众号菜单设计

> 定位：教程内容（前端 / 全栈 / AI 提效）+ 自研作品展示。
> 可用资源：网站或 H5 外链、GitHub 仓库、图文合集。
> 结构：3 个一级菜单 × 4 个二级菜单（每级留 1 个空位，方便后续加）。
> 点击类型说明：**关键词** = 用户点菜单后自动收到预设的图文回复；**网页链接** = 直接打开外链。

## 一、菜单结构

| 一级 | 二级 | 类型 | 触发 / 链接 | 用户看到什么 |
| --- | --- | --- | --- | --- |
| **学技能** | 前端实战 | 关键词 | `前端` | 4~6 篇 HTML/CSS/JS/框架实战图文 |
| | 全栈部署 | 关键词 | `全栈` | 后端、数据库、上线部署类图文 |
| | AI 提效 | 关键词 | `ai` | AI 辅助写代码、工具链相关图文 |
| | 全部文章 | 网页链接 | 合集 / 页面模板 URL | 一屏看全部历史文章 |
| **看作品** | 幼儿学堂 | 网页链接 | 站点 URL（待上线） | 打开即玩的单页应用 |
| | 在线工具 | 网页链接 | 网站工具页 URL（待建） | 自研小工具集合 |
| | 开源代码 | 网页链接 | GitHub 主页 / 仓库 URL | 跳转到代码仓库 |
| | 作品清单 | 关键词 | `作品` | 作品图文汇总 + 每件的一句话简介 |
| **找我** | 关于作者 | 关键词 | `关于` | 自我介绍 + 常驻联系方式 |
| | 加群交流 | 关键词 | `加群` | 微信群二维码 / 个人微信（图片） |
| | 合作投稿 | 关键词 | `合作` | 投稿要求 + 邮箱 |
| | 提问留言 | 关键词 | `提问` | 留言格式引导 + 常见问题 |

命名原则：一级 2~3 字、二级统一 4 字，扫一眼就知道点哪里。**「学技能」是内容入口，「看作品」是转化入口，「找我」是联系入口**——三者职责不重叠。

## 二、关键词自动回复规则（配置在「自动回复 → 关键词回复」）

| 关键词 | 匹配方式 | 回复内容 |
| --- | --- | --- |
| 前端 | 半匹配 | 图文消息：前端实战合集（建议 4~5 篇） |
| 全栈 | 半匹配 | 图文消息：全栈与部署合集 |
| ai / AI | 半匹配 | 图文消息：AI 提效合集 |
| 作品 | 半匹配 | 图文消息：作品清单 |
| 关于 | 半匹配 | 文字 + 个人介绍图文 |
| 加群 | 半匹配 | 图片：群二维码（**每周检查有效期**，过期必须换） |
| 合作 | 半匹配 | 文字：投稿要求 + 邮箱 |
| 提问 | 半匹配 | 文字：留言格式引导 |

要点：

- **用「半匹配」**，这样用户直接发「前端怎么学」也能命中。
- 每个关键词的回复里都放一条「全部文章」链接做兜底，避免用户翻不到想看的内容。
- 全匹配关键词（如 `ai`）建议额外加 `AI`、`AI 提效` 两个别名。
- ⚠️ **点击型菜单必须先配好对应关键词回复**：菜单发布后用户点了没反应，90% 是关键词没配或拼写不一致。
- ⚠️ 群二维码有效期 7 天，建议改成「回复个人微信号」或用长期有效的活码，省得每周维护。

## 三、上线前要补齐的东西

| 缺什么 | 怎么补 |
| --- | --- |
| 幼儿学堂可访问链接 | 单页面产物需先发布上线拿到 HTTPS 链接（可用内置发布能力一键生成分享链接） |
| 网站工具页 `/tools` | 放自研小工具的入口列表，每个工具一个子路径 |
| 全部文章链接 | 后台「内容与互动 → 合集」建一个合集，或建「页面模板」，取其链接 |
| GitHub 链接 | 确认仓库是 public，主页放 README 说明每个作品 |
| 群二维码 | 群满 200 人后只能邀请入群，建议同时准备个人微信二维码 |

## 四、配置步骤

1. 公众号后台 → **内容与互动 → 自定义菜单**（或「设置与开发 → 自定义菜单」）。
2. 先建 8 条关键词回复（第二节表格），逐条测试：用自己微信发关键词验证回复内容。
3. 再建菜单：
   - 三个一级菜单填「学技能 / 看作品 / 找我」，**只填名称、不设动作**（有二级时一级菜单本身不可点击，这是正常的）。
   - 每个一级下加 4 个二级菜单，按第一节表格填类型与内容。
4. 点「保存并发布」。**菜单发布后 24 小时内对全部用户生效**，已关注用户可能有延迟；自己测试时先取关再关注可立即看到。
5. 发布后再点一遍全部 12 个菜单项，确认每个都有正确响应。

## 五、已知限制与坑

- 一级菜单最多 3 个、每个二级最多 5 个，**菜单名长度后台有限制**（超了直接存不进），本方案都控制在 4 字内。
- 「网页链接」类型的外链**不校验域名白名单**，但域名若未备案或被微信拦截，用户会看到「该网页无法访问」——上线前用手机流量实测一遍。
- 菜单改动**需要重新发布**才生效，不是保存即生效。
- 点击型菜单的图文回复内容，改文案不用动菜单；但**关键词本身改了，菜单里的动作要同步改**。
- 后续扩展：等有 5 个以上分类时，把「学技能」的二级菜单换成「新手入门 / 前端 / 后端 / AI / 全部文章」，并把旧的分类页做成合集链接。

## 六、可选：用接口一次创建

公众号支持 `POST /cgi-bin/menu/create` 接口批量建菜单（需要接口权限，本项目 `.env.local` 里的凭据可直接取 access_token）。

适合的场景：菜单项多、需要反复调整，或想纳入版本管理。本仓库已有 `articles/push_to_wechat.py` 作为模板，改造成本很低——需要的话可以直接生成一个 `articles/setup_menu.py`（带 `--dry-run` 预览、`--delete` 回滚）。
